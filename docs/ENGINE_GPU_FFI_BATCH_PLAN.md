# 渲染全链路高刷计划（用户程序→渲染引擎→显示器）

> 状态：并批子项已收口（A 落地，B/C/D/E/零头无新代码结项，F 计时独立已合入）。
> 本计划管整条路：上层任意画面（任意图形、UI 组件库、2.5D 引擎等等）→场景组织→调度认速度→渲染干活→上屏显示，
> 在常用 60/120/140Hz 显示器上按显示器速度出帧、保证流畅。
> 目标：干活压到 6ms 以里（构建+重录+画画，等显示器的部分不算，跟着屏幕走）：
> 60Hz 格子 16.7ms 闭眼过，120Hz 格子 8.3ms 稳住，140Hz 格子 7.1ms 达标。
> 流畅的标准是等多久画面都不错位，动画位置按时间算。60Hz 真机按倍数折算验证，不等 120Hz 真机。
> 只走标准做法，非标准的不要。

## 0. 背景（一句话）

- 整链：上层画什么（示例/组件/2.5D/任意图形）→`ui/rendering` 组场景→`ui/scheduler` 按速度要帧→平台层报速度（Wayland/X11）→`render` 干活→`render/internal/gpu` 送 GPU→present 等显示器；哪段超预算都会卡。
- 25 秒鹈鹕剖析：跨语言门（purego `SyscallN` + `WriteBuffer/Draw/Set*`）占 44.6%，
  描边 Stroke 占 14.2%（模板构建 11%）。
- 并批子项已收口（54118e88 起）：模板填充 uniform 上 slab + cover 免传；A 期顶点 slab（扇形/包围盒/AA 带一次上传，绘制报偏移）；帧间隔口径正为显示间隔；F 期干活计时独立。
- 活窗现状（2026-09-23，Wayland，vsync=true）：鹈鹕 25 秒卡 0 次、p95 18.84/p99 20.22、构建 0.06/干活 0.33/等缓冲 5.87/等显示 7.19；图标 15 秒自检 3/3 过、基准图差 1 像素（0.0002%）、p95 18.47、卡 5 次；列表 15 秒 p95 18.35、卡 3 次（每分钟 12 次，超 5 次预算，门禁 FAIL）、图片 24/24、绑定 15。鹈鹕 T5/T12 出图正常（各 93600 点，1200×700），画画代码没动。机器波动大，单次不定论。

## 1. 目标与非目标

- 目标：同画面、同像素，上层任意画面在 60/120/140Hz 上都按显示器速度出帧、流畅；
  干活压到 6ms 以里（构建+重录+画画，等显示器的部分不算）；
  引擎认得 60/120/140Hz 的速度，按速度出帧，等多久画面都不错位；
  60Hz 真机按倍数折算验证；
  三窗（图标/鹈鹕/列表）先行验证，都受益，以后组件库/2.5D/任意图形走同路即沾光。
- 非目标：不动画面、不动接口、不动 present 语义；视频贴图路不动（另立项）；
  虚线砖贴化不做（0.82% 原理差，非标准，已撤回）。

## 2. 范围（整链五段；并批只是渲染段里的一块，已收口）

- 上层（用户程序）：示例/组件库/2.5D/任意图形，只调公开画图口；摆位布局、事件路由、演示开关走控制动词，不在上层写行为/动效/绘制。
- 组场景（`ui/rendering`/`ui/scene`）：形状组织、变换合成、缓存命中（平移归一化、几何缓存、文字图集），决定每帧要干多少活。
- 认速度（`ui/scheduler` + 平台层 + `ui/embedder`）：读真实刷新率（Wayland mode、X11 RandR、可变刷新上报），按速度要帧；拿不到信号才用兜底节奏；动画位置按时间算。
- 干活（`render` + `render/internal/gpu`）：构建+重录+画画压到 6ms；slab/粘滞/账本已落地（并批子项见下）。
- 上屏（present/swapchain）：Fifo 被动等显示器唤醒；干活和等分开记，不掺。

并批子项（渲染段内，已全部结项）：
1. 传数据继续并（已结项，无新代码）：slab 已落地（uniform+顶点一次上传）；剩绘制报号零头量极小（模板引用每画报一次 0、顶点报偏移），省微秒级，动对齐与语义风险大于收益，标准做法已覆盖（slab+粘滞+绑定账本）。
2. 虚线同形实例化（已结项，无新代码）：鹈鹕车道线是圆角矩形填充直画、不是虚线描边，
   示例已用位移变换摆位置，引擎里平移归一化本来就会命中同一份几何；硬做实例化省不出新量。
3. 损伤按实例包围盒并（已结项，无新代码）：跟着第 2 条走，E 没做成这笔也没意义；
   鹈鹕是全屏动的场景，本来就并不出小损伤，硬并不标准。
4. 变形细分抠算法（已结项，无新代码）：容差 0.1 已是标准做法，硬调大就是非标准；真变形的每帧只有两条腿的直线描边，本来就没有曲线可细分。
5. 计时干活和等分开记：干活（重录+画画）单记 6ms 口径；等的 Fifo 跟显示器走，不掺。
6. 同管线连画收敛（已结项，无新代码）：模板一路四段管线本来不一样，stencil 语义要求一路画完再下一路，能省的账本已省；剩每画报一次模板引用 0 是 pass 内常量，省微秒级，不值得动。
- 在外：示例层只做验证（不绕引擎）、present/swapchain 语义不动、视频解码与播放链路另立项。
- 待排（整链新活）：G 认速度核验（60/120/140 三档要帧+上报+兜底）；H 上屏等待拆分（等缓冲/等显示各归位）；I 上层复用核验（组件/2.5D 走同路即沾光，逐个真窗验）。

## 3. 对齐标准

- 节奏跟显示器：等开工信号出一帧（Skia/Flutter 同款）；信号不到才用兜底；可变刷新有人上报就换节奏。
- 干活分三线程：组场景、画图、送显示各干各的，中间排两帧流水。
- 缓存优先：画过就存（形状/文字/图片/管线/显存块），着色器提前编好，第一次跑也不卡。
- 少画：屏外跳过，只重画脏块，小图拼大图集一次送。
- 送得省：Slab 打包：照贴图路现成套路（256 对齐、增长带余量、旧板延迟退、管线重建换绑定）。
- 粘滞跳过：字节/指纹一样就跳过（浏览器/Skia 同款省法）。
- 内容频率跟显示器：已落地（Wayland 读 mode、X11 读 RandR），本计划不再动节奏。
- 非标准一律不要：贴砖配容差、写死频率、示例层绕引擎，全部不收。

### G 在干什么、为什么、目标是什么

- 干什么：核验三档速度下要帧节奏对不对。读真实刷新率，按速度要帧，速度变了换节奏，拿不到信号走兜底，动画位置按时间算。
- 为什么：现在 p95 在 19ms 左右，慢的 5 帧赶不上 60Hz 的 16.7ms，只能多摆一张旧画面，这就是看到的蹦一下。节奏不对，后面干活再快也白搭。
- 目标：60 按 16.7ms、120 按 8.3ms、140 按 7.1ms 要帧，要帧数对上，慢帧不再错位。

### H 在干什么、为什么、目标是什么

- 干什么：把等的两段拆开看。等空闲缓冲和等显示器各记各的，排队满了顺延下轮，不硬挤。
- 为什么：干活只有 0.4ms，整帧 19ms 里剩下的全是等。等在哪段不清楚，就没法下手。
- 目标：三段尺子数对上，慢帧定位到段，19ms 收回 16.7ms 以内，再往 8.3ms、7.1ms 收。

### I 在干什么、为什么、目标是什么

- 干什么：组件库、2.5D、任意图形走同一条路，每个逐个开真窗验像素、帧间隔、人工看。
- 为什么：引擎修好了，上层绕开引擎另搞一套就白修了。沾光的前提是走同路。
- 目标：三窗先行验证通过，后续每个上层逐个真窗达标，不在上层写绘制和动效。

每期独立验证、独立提交（video 及别线一概不带，推送另行确认）。

## 5. 验证矩阵（每期必跑）

- 构建：`gofmt -l` 干净；`go vet` 无新增（存量 `unreachable code/unsafe.Pointer` 除外）。
- 单测：`render/internal/gpu` 全包 + `render` 包 + `ui/scheduler` + `ui/embedder`
  逐文件跑（禁止一次全量，参照既有纪律）。
- 像素：鹈鹕 T=5.0 与 T=12.0 两时刻 Golden，抽样 93600 点 0 差（容差显式声明）。
- 活窗：鹈鹕 25 秒 + 图标 15 秒 + 列表 15 秒，Wayland；记录 hitch/p95/p99/构建/干活/等缓冲/等显示；
  60Hz 真机按倍数折算 120Hz（8.3ms 格）/140Hz（7.1ms 格）；
  干活看 6ms，整帧看各档格子，错位看跳帧与位置准；
  机器状态波动大时做干净对照（撤掉改动重跑），不拿单次噪声下结论；
  每期人工看 1 分钟确认窜感（数只管帧间隔，眼管顺序感）。
- 文档：公开 API 有变才同步总账；否则修订表记一行。

## 6. 风险与兜底

| 风险 | 等级 | 兜底 |
|---|---|---|
| 顶点偏移错一位整屏花掉 | 高 | 逐像素门禁卡死；偏移计算单测先行；失败帧不污染下帧 |
| 板增长时在途命令野绑定 | 高 | 旧板延迟退（RetireBuffer）；绑定 epoch 对账 |
| 管线重建后绑定指向旧布局 | 中 | epoch 变化整批换绑；per-entry 布局检查保留 |
| 驱动对非零 Offset/Size 挑剔 | 中 | 只用已在线的偏移绑定画法（贴图路同款）；出问题整期回滚 |
| 活窗噪声误判优化无效 | 低 | 干净对照 + 多跑取稳态；噪声大时只认像素与单测 |

- 任何一期像素门禁不过：整期回滚，不带病合入。
- 工作区 video 及别线改动一概不碰；提交前 `git status` 对清单。
