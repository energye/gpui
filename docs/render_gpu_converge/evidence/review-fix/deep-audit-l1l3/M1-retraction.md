# M1 核查与撤销（原登记：半透明填充 GPU/CPU 色空间分叉）

## 原登记（D9 标定期间，2026-11-03）
> `fillMaskedAsImage` 兄弟路把 premul 栅格喂进按 straight 解释的合成链——GPU 半透明填充
> `SetRGBA(1,0,0,0.5)` 画矩形实测 (255,127,127,255)（当时推算"正确应 ≈(128,255,255,~128)"），
> CPU 档直画正确 → 判为 GPU/CPU 分叉。

## 核查结果：**结论错误，予以收回**（同日 M1 专项）
错在两处，都如实记下：
1. **"正确值"推算错**：把 `Pixmap.getPremul` 的**存储约定**（premul）错误套到了 fill 的**源数据**上。
   引擎里 `SetRGBA(1,0,0,0.5)` 是 straight 语义输入，合成按 straight 解释 pixelData——
   解析真值就是 (255,127,127,255)，(128,255,255) 那个数是拿 premul 公式二次乘出来的幻影。
2. **对照实验缺失**：登记时只测了 GPU 一档，没跑 CPU 同姿态；补测后两档逐位一致。
   另踩了判别力坑：首轮鉴别探针用 coverage=128，而 128/255≈(128/255)^(1/2)·255 附近
   straight×cov 与 premul×cov 两式简并（实测同为 (255,191,191)），换 coverage=100 后仍一致。
