## 3 四窗 golden fail-open → fail-closed（本批实修）

原写法（`ui_wr_p31:306`、`ui_wr_p32:367`、`ui_wr_p33:356`、`ui_wr_p34:331`）：

```go
golden := loadImage(goldenPath)
if golden == nil || os.Getenv("GPUI_ACCEPT_GOLDEN") == "1" {  // ← 缺基线无条件播种
        ...写基线...
        return 0, 0, true                                       // ← firstRun=true
}
...
if !goldenFirstRun && goldenDiffPct != 0 { fail(...) }          // ← firstRun 时整条断言被跳过
```

后果：基线一旦被删/缺，窗口**无条件 PASS**（还顺手把当次画面写成新基线），与 `examples/wrkit/evidence.go:30-38`
`GoldenGate` 的 fail-closed 标准相悖（该标准要求"缺基线必须显式给 `GPUI_ACCEPT_GOLDEN=1` 才播种，且播种那一跑不算过"）。

改法（四窗同一形状）：`evaluateGolden` 返回加一维 `(diffPct, totalPx, seeded, missing)`；缺基线且没给 env ⇒
`missing=true`；门禁段拆成三态——missing 判红并给出补基线的正确指令、seeded 判红（"这一跑不算过，review+提交后复跑"）、
只有真比对且 diff≠0 才按原口径判红。

A/B 实测（`RUN_SECONDS=6 -auto-only`，`WGPU_NATIVE_PATH`/`LD_LIBRARY_PATH` 已导出；GNOME Wayland + 无根 Xwayland）：

