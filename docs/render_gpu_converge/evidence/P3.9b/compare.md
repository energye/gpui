# P3.9b 1x/4x MSAA 真实窗口动画性能对照（2026-11-09）

> 场景：满屏 1920×1080（实际 content 1868×1021，带装饰）混合通用动画——3×3 mesh gradient 背景、三条贝塞尔曲线、四张旋转圆角卡片带文字、旋转缩放图片、半透明 SaveLayer 圆盘、40 粒子、线性/径向渐变带、锚点色卡；`PresentPolicyFullPaint` 每帧全量重绘，相位持续推进。
> 硬件：GNOME Wayland / NVIDIA 940MX **1024 MiB** / 驱动 580.178.04 / 1920×1080@59.88Hz。
> 每轮 18s、串行、单窗、程序自己 `RunFor` 正常退出；无并发、无硬杀、每轮前健康检查。
> 数据：`measure/*.json`（`wrgate.BuildReport` 原始字段）。

## 0 直话（回答「4x 很占内存和性能吧」）

**是，在满屏复杂动画下 4x 的代价很实在。** 同一后端 native、只差 MSAA 的干净对照：

- **显存**：稳态 device-surface 62.8 → 76.3 MB，但**峰值 62.8 → 147.8 MB（2.35×）**，超过 128 MiB 池预算，触发 5 次淘汰。
- **帧率**：55.95 → **42.01 fps（掉 24.9%）**，p95 22.30 → 27.45 ms，hitch 2 → 8 次。
- **按本库性能红线**：1x 的 `fps_interval=55.95 ≥ 55` 勉强 PASS；**4x=42.01 直接 FAIL FPS 门禁**；p95 两者都 >22ms（1x=22.30 已压线，这个满屏复杂场景在 940MX 上 1x 本就接近极限）。
- 首帧几乎不变（115→121ms，+4.6%）；RSS 峰值不变（+0.1%）；CPU 光栅占比 111%→118%（多线程归一，CPU 侧一直是主瓶颈）。
- **没有 OOM 降级日志**，4x 确实生效（显存涨、画面正常非黑）——所以上面是"真 4x"的代价，不是降级后的假象。

## 3 与上一轮静态小窗诊断的差异（为什么这份更可信）

上一轮 P3.9a 临时诊断（静态 1200×800 窗）：显存 11.5→65.3 MB（5.67×）、首帧 113→135 ms、**帧时基本不变**——因为那窗是静态、CPU 侧瓶颈（cpu_raster≈90%）、GPU 有大量空闲。

本轮是**满屏 + 每帧全量重绘 + 复杂动画**，GPU 真正被压满，所以 4x 的代价暴露出来：帧率掉 25%、p95 越过红线、显存峰值翻倍。结论：**4x 掉不掉帧取决于场景是否把 GPU 填满；静态小窗"没掉帧"不能外推到满屏动画。**

## 5 使用场景结论（回答「mesh 和 4x 的使用场景」）

- **mesh gradient**：低成本生成连续颜色场（UI 背景/卡片/启动页/主题渐变），分辨率无关、每帧可改顶点做动画；本场景里它是背景大面积曲面，1x 有硬边锯齿、4x 更平滑——但锯齿代价是全局的，不能只为 mesh 开。
- **4x MSAA**：当窗口主体是斜边/曲线/三角网格等**解析 AA 覆盖不到**的图元、且 GPU/显存预算充足（桌面独显、高端移动、展示/截图窗）时才划算。
- **本硬件（940MX/1GiB）+ 满屏复杂动画**：4x 掉 25% 帧、p95 破线、显存峰值 2.35× 且触发淘汰，**不划算**。默认 1x 是对的。
- **1x 下要顺滑**：路径/文字/圆角本就有解析 AA（本场景这些图元 1x 也平滑）；mesh 的曲面硬边是 Skia `drawPatch` 标准口径。要更顺滑要么局部超采样（非标准，用户已排除）、要么开全局 4x（本硬件代价如上）。
