Command ui_wr_r16_warmup is the W0 R16 real-window: 首帧/WarmUp/恢复.

    export LD_LIBRARY_PATH=$PWD/lib WGPU_NATIVE_PATH=$PWD/lib/libwgpu_native.so
    RUN_SECONDS=5 go run ./examples/ui_wr_r16_warmup -auto-only -gate-stage pre
    RUN_SECONDS=5 go run ./examples/ui_wr_r16_warmup -auto-only -gate-stage post
    go run ./examples/ui_wr_r16_warmup                 # manual: animate until close
    go run ./examples/ui_wr_r16_warmup -manual-seconds 15

Window: 1200x800. RUN_SECONDS>=5 (U16). GPU window required.

Evidence (U21): the gate has two deterministic stages so both halves of R16 are
pixel-asserted:
  - pre: first-frame content is frozen (steady phase, no recovery); the final
    snapshot is content-equivalent to the first frame because every visible body
    node is placed before Open() and nothing animates.
  - post: recovery is triggered at a fixed tick and the recovery state is held
    to the end; the snapshot proves the full-tree repaint survived.

Each stage writes its own GPU-readback PNG, pixel probes, and bitwise golden
(header + legend + body; the live HUD band is excluded). Manual mode keeps the
Steady→Spike→Recover animation and the one-second recovery banner.
