- 除 `view_raw_attack_test.go` 的诊断行号因顶部加标签后移 2 行（11→13）外，默认标签结果与 P1.2b 修复前逐字节一致。

## 1 执行命令与过滤口径

```bash
# 1) 原始两轮（预期只剩已知问题包）
go vet ./...
go vet -tags nogpu ./...

# 2) 枚举包；TODO 过滤：
#    - 去掉 examples/ui_wr_t_stress（已知加载失败，无法分析）
#    - 保留 len(GoFiles)+len(CgoFiles) > 0 的包
#    - 额外保留 len(TestGoFiles)+len(XTestGoFiles) > 0 的包（ui/scene/internal/gpupixel）
go list -e -f '{{.ImportPath}}|{{len .GoFiles}}|{{len .CgoFiles}}|{{len .TestGoFiles}}|{{len .XTestGoFiles}}' ./...

# 3) 过滤后逐包分析（包清单见 evidence/P1.2b/packages-default.txt / packages-nogpu.txt）
go vet $(cat packages-default.txt)
go vet -tags nogpu $(cat packages-nogpu.txt)

# 4) nogpu 测试编译验证（不跑测试，只编译测试二进制）
go test -tags nogpu -run '^$' $(cat packages-nogpu.txt)
```

- 默认清单 352 包，nogpu 清单 348 包；差值 4 是只在默认标签下存在的 GPU 示例包：
  `examples/render_gpu`、`examples/render_scene_gpu`、`render/examples/compute_clip`、`render/examples/compute_pipeline`。
- `go vet` 默认包含测试文件（`-tests` 未关闭），所以测试辅助代码的问题也在本基线内。
- `go vet` 是静态检查，不执行测试、不开窗、不建 GPU 设备。
