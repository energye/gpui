# antd 组件开工流程（先流程后组件）

> 目标：每份 `docs/antd/*.md` 只看自己就能开工。现在不做组件，先把流程和文档缺口补齐，后面再按依赖顺序并行做组件。

## 1. 开工前置（L0 地基，先行）

- 套件架子：新建 `ui/kit`（或定死文档里的 `primitive/core` 改映射到现有包的对照表），否则所有 §6.10 Go 签名无处落笔。
- 示例目录：新建 `examples/ui_polish_gallery`（一控件一页），或书面改指到现有入口；在落定前 §6.12 第 5 条视为悬空，不算完成。
- 覆盖记录：落定 `coverage.go` 位置与 Notes 写法；在落定前 §6.12 第 6 条视为悬空。
- 主题扩容：`ui/theme/tokens.go` 只有十几个变量，补齐分割线色、次级文字色、控件高度、内外边距、阴影、遮罩色对照表，否则 L2 断言接不上。
- 浮层定位：`ui/overlay` 补十二方向定位、贴边翻转、箭头、外点关闭、焦点锁；否则下拉、菜单、弹窗、抽屉、提示类做不出。

## 2. 文档就绪标准（每份必须同时满足）

1. 参数全：类型、默认值、版本齐，关键项在正文有绘制说明。
2. 示例全：非调试示例一个不漏，裁掉的写明去哪一期。
3. 度量有数：宽高行高边距圆角字号可断言，能映射到主题变量或回落常量。
4. 交互有状态机：规则编号化，只写适用的态，不套模板。
5. 平台边界写死：浏览器能力写明映射还是不做。
6. 接口用例可落地：Go 签名具体，用例一步一期望。

## 3. 完成标准（单组件）

- §6.8 P0 全实现；§6.9 P0/L1/L2 用例全过；L2 度量断言过；L3 至少一个关键态截图；示例页更新；覆盖记录更新。

## 4. 级联依赖顺序（供后面并行用）

- L0：地基（套件架子、主题扩容、浮层定位、示例目录、焦点手势补齐）。
- L1：无依赖基础件（按钮、标签、分割线、间距、浮层弹性盒、栅格、图标注册、加载圈、骨架、统计、时间线、水印）。
- L2：依赖 L1 的组合件（头像、徽标、提醒、卡片、折叠、描述、空态、页签、步骤、开关、进度、评分、二维码、 Gast 浮层提示）。
- L3：依赖浮层加表单件（级联、日期、时间、提及、选择、树、树形下拉、穿梭、表格、菜单、下拉、抽屉、弹窗、通知、消息、图片预览、上传、漫游、锚点、固钉）。
- L4：表单聚合（表单本体绑定校验联动）。
- L5：全局（配置、应用全局件最后，等消息弹窗通知就绪）。

同级可并行，跨级必须等上游就绪；每个任务只改自己分到的文件。
