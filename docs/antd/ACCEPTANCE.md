# kit 统一验收标准（所有控件共用）

版本冻在 antd 6.5.1。单个组件的特殊数补进它那份 `docs/antd/<名>.md` §6，不另起炉灶。
本文件的每条后面都标了出处：F=Flutter，A=antd 官方，G=Gio，W=本库真窗。

## 一、每控件七件套（缺一件就不算完）

抄 A 的做法：每个组件固定七个测试文件，新 demo 自动被测。
抄 F 的做法：行为、录制、截图三证据缺一不可。

1. 行为：组件是外观 + 行为 + 功能，不是样子。外观对 Token/度量，
   行为对 antd 交互（悬停/按压/聚焦/禁用/键盘/气泡/拖拽/开关），
   功能走完整链路（可关真关、可点真调、受控非受控、值回写）。
   单测灌事件查状态（抄 G 的 `Queue→Layout→Frame→Reset` 三段，
   断焦点、回车激活、禁用吞事件、受控非受控，每个 §6.9 用例一个测试名），
   真窗再点一遍：能点中点得动，动了重画 involving 脏区，禁了点不动。(F/G/W)
2. 布局矩阵：Exact/Min/Max 三种约束各跑一遍，断尺寸，不用 GPU。
   图标只断尺寸那种也算，但每个组件必写。(G)
3. 录制断言：PaintVisits 脏局部用例是强制的。全量画一遍记个数，
   脏一个再画，第二次必须远小于第一次，且布局次数不涨。
   钩子是引擎现成的（`ui/rendering/paint_context.go`），用法抄
   `render_matrix_test.go`。光“画过”不算，必须证明“只脏局部”。
   模板见 `ui/kit/icon/dirty_test.go`，以后每个组件照抄：根下挂自己、
   挂 20 个静态块、再挂一个兄弟，改自己断局部。(F/W)
4. 截图：showcase 大图进 testdata，测试读文件比。每个可见组件必须有一张
   showcase 大图：一张画布上按 §6.8 主路径把多种式样摆全
   （按钮的 Type/Size/禁用/loading/图标/多按钮/幽灵/危险/Block/变体各一行，
   提醒的基本/四种/无边框/可关/描述/图标/顶部公告/轮播/操作各一行，
   余类推），测试重画一张跟它比。CPU 直画允许抗锯齿容差
   （单通道差 12 以内，超差像素不超千分之五，单像素超 64 直接挂，
   `UPDATE_GOLDEN=1` 可重制底图）；真窗静区逐位一致，首跑产基线，
   次跑起差一像素就挂。字必须是真字，禁止画黑条代替：
   没字体时宁可空着也不许画黑条，有字体时字区必须有墨。(G/F)
5. 示例：画廊是交互验收台，不是截图陈列。官方非调试示例里，
   P0 + P1 一个不少进画廊（真做不了的在测试里 Skip 并写清原因，
   不许静默丢）。窗上每段摆完整真组件（动作按钮摆真按钮，
   不是蓝色块），段数与 §6.8 P0 示例数对齐，段条随内容长高不裁剪，
   超出视口的段也在树上挂着（拉高可见，不许丢段）。
   画廊事件主干：鼠标移动有悬停、按下去有按压、松开有点响应、
   键盘 Tab 走得到、回车空格按得动、该出的气泡出、该关的关得掉；
   只画不点不算完。画廊页能单独开单独测单独截图；
   新增示例零配置即被测（glob 自动发现）。(A/W)
6. 无障碍：四条现成尺子——最小点 44px、文字对比度、有名可读、读屏树正确。
   装饰件默认不抢焦点，有名字的才报。(F/A)
7. 主题镜像：三主题截图（默认/暗/紧凑）；从右向左包一层快照；
   主题统计文件改了必须一起更新。(A)

## 二、性能：静态看少画，热点看稳帧

这是上一版写错的地方：静态窗本来就只有几帧，有两三帧就是满分，
拿 55 帧去卡它必挂。两种窗两种判法：(W)

- 静态窗（按钮常态、骨架占位、徽标）：跑 5 秒，能出 2 帧就行。
  判的是稳住之后不再画：布局次数和绘制次数不再涨，
  没脏的边界一直回放（skip 只增），脏区接近 0。
- 热点窗（转圈、滚动、扫光、图流）：时长跟引擎档走，
  动画类 30 秒、滚动压力类 60 秒，不自创 5 秒一刀切。
  判的是稳：frame 间隔反推的帧率 ≥55（看 interval，
  不看含开关销的 wall 值），95 分位 ≤22ms，卡顿 ≤5 次/分，
  信号来源必须报（fallback 不许冒充锁 60Hz）。

分层抄 F：小步用秒表测 build 耗时（单测里跑 15 秒取平均），
大步用真窗采帧时间加内存加回收并落 JSON。(F)

测法直接抄现成的例子窗，不自创：

| 要验什么 | 抄哪个例子 | 关键数 |
| --- | --- | --- |
| 内脏了外头不动 | ui_wr_r3_boundary | 脏的那格重录，没脏的回放 |
| 动画盖在静区上 | ui_wr_c5_anim_over_static | 静区重录是 0，绘制次数漂移有上限 |
| 大列表只建可见行 | ui_wr_r7_virtlist | 建了多少比总数少一个量级 |
| 图来了只脏一格 | ui_wr_r10_async_image | 一批最多重录到达格数加一 |
| 透明分组超预算拒批 | ui_wr_r18_savelayer | 预算按窗设定，允许和拒批都要计数 |
| 缓存超上限淘汰不断 | ui_wr_r14_cache_budget | 条目触顶且不超预算，淘汰计数只增 |

- 红线：不许靠降画质凑帧数。
- 一个控件不一定开两个窗：一个窗里分稳/冲/收三段跑就行，
  收段判静态，冲段判帧率。71 个控件也不必个个开长窗：
  逻辑和计数能单测的走单测，长窗只给三类代表开（见资源一节），
  画廊页负责人眼和截图。
- 指标走 `wrgate` 那一套上报，字段缺了直接挂，
  不许默默省略，不许默默置零。

## 三、资源：分三种组件加码

抄 G 的做法：缓存只断“满了踢最老”，性能只做“静/动两套 bench 对照”，
不设拍脑袋的红线；长跑斜率看真窗。(G)

- 小件（按钮标签徽标）：静态窗 CPU 本来就低，这是正常的，
  不判它；内存不涨，关了看得见释放。包体积单独卡一次。(A/G)
- 大数据（表格列表树下拉）：只建看得见的行，长跑内存斜率有预算，
  短窗（15 秒内）可声明免掉斜率门，但要写进 README 并复审。
- 图文动效（图片头像加载圈骨架）：图走异步解码，不卡主线程；
  缓存有显式上限，超了淘汰，淘汰计数只增，画面不断。
- 反过来：热点窗 CPU 全 0 就是造假，直接挂（静态窗不适用这条）。

## 四、渲染：三看

- 清晰：1 像素线不糊，圆角不毛，字不虚。
- 省：透明旋转裁剪走层，不每帧全树重录；默认走保留策略，
  稳态脏区远小于 1，全量重画就老实标全量。
- 底图格式抄 G：逐像素比走人眼差（颜色差 0.01、透明差 8 以内），
  另加单点探针和“连跑 3 帧验缓存”。(G)

## 五、引擎用法：用对接口，不绕路

| 场景 | 用这个 | 不用这个 |
| --- | --- | --- |
| 会动的子树 | 设重绘边界 | 整树重画 |
| 大列表 | 虚拟列表，只挂视口加两行缓存 | 一次全建 |
| 图到了 | 只标画脏，不碰布局 | 顺手重排 |
| 多图共用一张 | 共享图，不转移归属 | 每格一份拷贝 |
| 透明分组 | 离屏层，次数按窗设预算 | 无限制套娃 |
| 动画节拍 | 调度器节拍器，不转就不占帧 | 常开渲染 |

## 六、工业级对齐（2026-09-14 起，目标：与 antd 同款行为）

只画样子不算组件。antd 的工业级在于：配置全（API 一个不少）、
状态全（hover/press/focus/disabled/loading 互斥正确）、反馈全
（点有响应、错有提示、等有进度）、键盘全（Tab 进得去、回车空格按得动、
Esc 退得出）、组合全（能嵌表单、能进弹窗、受控非受控都对）。
本库按此验收：

1. API 对齐：§6.10 的 Go 签名与官网 API 一一对应；官网有、我们没有的，
   要么补上，要么在测试里 Skip 写清平台原因，不许静默少参数。(A)
2. 交互状态机：每个可交互组件有状态流转（idle→hover→press→idle，
   disabled 全吞，loading 转且防重），单测断流转，真窗点一遍看反馈。(A/W)
3. 键盘与焦点：可聚焦组件 Tab 到得了、有焦点环、回车空格能激活、
   Esc 能退出（适用者）；展示时不抢焦点。(F/A)
4. 真窗见真家伙：画廊每段摆完整真组件，动作按钮摆真按钮不许摆色块；
   段数与 §6.8 对齐，段条随内容长高不裁剪，超视口的段也在树上
   （拉高可见，不许丢段）。(W)
5. 一组件一张大图：showcase 大图进自己目录 `testdata/showcase_<名>.png`，
   一张画布按 §6.8 摆全多种式样，测试重画比对（容差见本文件第一条
   第 4 款，`UPDATE_GOLDEN=1` 重制）；字是真字，有字体时字区有墨，
   没字体宁可空着，不许画黑条。(G/F)

## 七、机器锁：两道门禁替人盯着

光写文档没用，得有机器每天卡。两道门禁，跑 `go test` 自动执行，
负向验证过（删用例、删页都会挂，见下）：

- kit 中央门禁（`ui/kit/acceptance_test.go`）：覆盖表里只要不是“未开工”，
  就查七件事——P0 用例号在测试名里全出现、调过 Layout、
  有 PaintVisits 脏局部用例、testdata 有文件、断过焦点或角色、
  读过主题、没碰显卡包没写本机路径。
  想标“首批完”先把测试补齐，否则合不进去。
- 画廊侧门禁（`examples/ui_polish_gallery/acceptance_test.go`）：
  已开工控件必须有同名页，页的文档与覆盖表对得上，
  能独立打开，导航里找得到。组合窗不代替单能力，机器替人查。

长窗（30/60 秒）和真机帧率内存，由发版前的人工链跑，不进每次提交的门。

负向验证（2026-09-13）：改名一个 PRD 用例 → kit 门禁挂
`缺 P0 用例 ICO-18 的测试`；改名 icon 页 → 画廊门禁挂
`已开工但画廊没页`。两处验证后文件已恢复。
