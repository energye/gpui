# 并行光栅 + 提交并批（新开工单）

> 目标：画质按现代高清只升不降，性能靠并批和省光栅 CPU 换。
> 状态：2026-10-03 立项。T（界面/光栅/图片三线）已闭项，本单只做帧内并行 + 提交并批，不碰三线归属。
> 真源：`docs/ENGINE_THREAD_T_PLAN.md`（三线）+ 本文件（帧内分批）。

## 需求

1. 画质只升不降：静止帧与改前逐位一致，门禁像素差零增长。
2. 并批：同材质同状态顺手并成一批，一次提交 1700 多条里 1500 来条状态切换压下去；模板共享状态绕开不动。
3. 省光栅 CPU：脏层才重放；刚体烘一次转着贴；药丸底烘一张九宫格拉。
4. 多线程：录制分路并行，最后合拢一次交，显示点对拍子；池常驻、核不够自动缩、关窗即收。

## 非目标

- 不改三线归属（RO 树归界面线、`render.Context` 归光栅独占、图片线不动）。
- 不做降质：分辨率/特效只升不降。
- 不一次全上：一批一验，红即回滚当批。

## 分批顺序

| 批 | 做什么（落点文件） | 自测门 |
|----|-------------------|--------|
| B1 并行光栅 | `ui/scene/rasterize.go` 脏层任务切分 + 工人池（固定常驻，核数-1，两核以下/任务<2层直串行）；每路私有草稿区；字形进图集排队；合拢按层号排序 | 单测绿 + `-race` 干净 + 离屏对比零增长 + 低核（GOMAXPROCS=2）对照串行一致 |
| B2 提交并批 | 提交端同材质同状态 coalesce；零角度/静止走老路；模板语义单测锁死 | 单测绿 + 像素逐位 + 提交条数下来 + 双后端真窗 |
| B3 后台烘焙+兜底 | `bakeTile` 类后台化；失败/核不够全兜底串行；三重验（单测+离屏+双后端真窗） | 同上 + 关窗无后台残留 |

## 线程池规矩（用户定的五点 + 核不够）

- 固定大小常驻：启动按 `NumCPU-1` 开，不随帧起落；关窗统一收，不留后台线程。
- 任务按层号：脏 PictureLayer 每层一任务，序号即层序；<2 任务不分。
- 数据不串：每路私有 display-list 草稿 + 剖分器（沿用 `fanTessellatorPool` 思想，每路一具不清堆）；字形图集/纹理缓存写入排队。
- 合拢一次交：`WaitGroup` 人到齐，按层号排序后单线程一次 `Submit`；模板/混合/裁剪状态只在合拢后碰。
- 内存复用：沿用写缓冲桶/命令池套路，帧内零申请；失败一路即整帧回串行重跑。
- 核不够：两核以下直接串行；排队比干活久自动减一路；`GOMAXPROCS=2` 是必测项。

## 标准对齐

- Chromium 合成器（多光栅线程 + 单 GPU 主线程）、Flutter（UI/Raster 双线）、Skia（分块并行）：前面分路录，后面合拢交，GPU 异步画。
