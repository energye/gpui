# Phase 4 — L1 加深（滚动 · 文本 · 图像 IO）

## 目标

在 P3 管线不变的前提下，让 **真页面素材**（长列表、字、图）也能维持帧成本∝脏区。

## 非目标

Ant List/Table 产品 API；完整 IME 编辑器产品；L2 手势竞技场。

## 能力块（大纲）

| 块 | 内容 | 对应 F/场景 |
|----|------|-------------|
| **滚动协议落地** | Offset/Transform Layer；虚拟化挂载可见 RO；bind 上界 | F05 · S5/S6 |
| **嵌套滚动（最小）** | 父子竞争规则草案（完整竞技可放到 P5） | — |
| **文本加深** | shaping 缓存、atlas 命中、多行基础 | F10 加深 |
| **图像** | **IO 线程**解码；上传队列；占位 | F12 |
| **裁剪** | clip rect/rrect 与滚动裁剪一致 | — |
| **saveLayer 纪律** | 默认禁止大面积；有预算接口 | F16 起步 |

## 门禁方向（细卡时钉数字）

| 场景 | 方向 |
|------|------|
| S5 1k 行虚拟列表滚动 | 每帧 mount/paint 节点有上界；输入延迟 ≤1 帧 |
| S6 拖拽滚动 | 最新点跟手；不整表 markNeedsLayout |
| 大图列表 | 解码不堵 UI 线程（F12） |
| 文本编辑光标（若做最小） | 仅光标 boundary 脏 |

## 依赖

- P3：Layer、管道、Ticker、render 热路径可用  
- 可能改 `render` 文本/图 atlas、`gpu` 上传  

## 细任务触发条件

✅ P0–P3 已收口（[`ENGINE_L1_CLOSEOUT.md`](./ENGINE_L1_CLOSEOUT.md)）。  
建议：开 P4 细卡前存一份 `ui_l1_spinner` JSON 作 baseline。

# Phase 5 — L2 框架壳（控件前底座）

## 目标

复杂交互 **不必** 每个控件自写一套：手势、焦点、浮层挂载、动画 API 完备。

## 非目标

Ant Modal/Button 皮肤与产品 API（那是 P7）；完整 a11y 生态。

## 能力块（大纲）

| 块 | 内容 | 说明 |
|----|------|------|
| **GestureArena** | 识别器竞争、点击/拖/滚轮 | 对齐 Flutter gestures 思想 |
| **Focus** | 焦点树、Tab 遍历、键盘路由骨架 | 输入类控件依赖 |
| **Overlay 机制** | band 填满：插入/移除/命中序 | **机制**不是 Ant Modal |
| **Animation 完备** | Curve、状态、隐式动画默认 compositor-only | F09 完整 |
| **Semantics 最小** | 角色/标签骨架 | 可很薄 |
| **主题/Token 传播（最小）** | 全局配置下发接口 | 命令式也可 |

## 门禁方向

| 项 | 方向 |
|----|------|
| 手势 | 点击与拖不冲突的单测矩阵 |
| 焦点 | Tab 顺序、焦点环不破坏脏区模型 |
| Overlay | 浮层在内容层之上；不逼 main 全量矢量 |
| 动画结束 | 自动 IDLE（F09/F17） |

## 依赖

- P3/P4 事件与 HitTest 稳定  
- Overlay band 在 P2 已预留  

## 细任务触发条件

P4 滚动/IO 主门禁通过（或书面同意并行时 P4 末启动大纲细化）。

# Phase 6 — L1 增强（合成 · 多窗 · 工具）

## 目标

逼近系统级合成效率与可观测性；**不改变** P3 语义契约。

## 能力块（大纲）

| 块 | 内容 |
|----|------|
| **更细 damage** | dirty rect / 脏层 blit 面积收敛 |
| **OS damage** | 后端支持则接；不支持则应用层仍省 |
| **RasterCache** | 静态复杂子树晋升纹理、预算淘汰 |
| **多窗口** | 每窗 Scheduler/PresentTarget；Device 策略（共享串行） |
| **性能 HUD** | 帧时间线、脏区可视化、pipeline_depth |
| **Present 策略** | fifo/mailbox 等可配置（F18 深化） |

## 门禁方向

| 项 | 方向 |
|----|------|
| 局部脏 | 合成/上传量随脏面积降（相对 P3 基线） |
| 多窗 | 单窗不回归；双窗无串扰泄漏 |
| HUD | 开发开关，默认 off |

## 细任务触发条件

有真实瓶颈数据（P3/P4 JSON）后再拆优先级，避免空优化。

# Phase 7 — L3 产品控件（Ant）

## 目标

`docs/antd` 控件迁入；**只**依赖 L1+L2；禁止直触 GPU。

## 非目标

改引擎脏区模型；为单控件开私有 Present 路径。

## 能力块（大纲）

| 块 | 内容 |
|----|------|
| **包** | 如 `ui/kit` 或独立 `kit`（实现时定，依赖纪律不变） |
| **波次** | 按 antd 目录分批：通用 → 布局 → 导航 → 表单 → 数据展示… |
| **纪律** | 动画走 Controller；动效默认 RepaintBoundary；无 gpu import |
| **验收** | 行为对照 antd 文档 §；视觉可 golden/抽样 |
| **主题** | Token/Skin 换皮 |

## 门禁方向

| 项 | 方向 |
|----|------|
| 依赖 | kit ↛ gpu；kit ↛ 绕过 Layer 的全屏刷帧 |
| 单控件 | 启动动画后 NonBoundary 脏为 false（或等价指标） |
| 回归 | L1 S0/S2/S4 不回退 |

## 细任务触发条件

- L1 §7.1 已勾  
- L2 手势/焦点/Overlay **至少可用**  
- 按控件波次单独开任务卡（不要一份写完所有 antd）

# §L1 验收：怎样算「原生级引擎手感」

> 对应问题：L1 完成后如何验证？能否保证 CPU/内存/FPS「最优」正向优化？

## 1. 「原生级引擎手感」的**工程定义**（可测）

本仓库 **不**宣称「数学上全局最优」或「永远低于某商业引擎每一个周期」。  
**宣称的是：** 在固定场景矩阵下，行为与成本模型对齐 Flutter 生产管线，且 **门禁数字达标**。

| 维度 | 原生级（L1 关门）含义 | 主要证明 |
|------|------------------------|----------|
| **静止** | 无事不空转 | S0：CPU≈0，无多余 Present |
| **局部性** | 成本∝脏区 | S2/S4：`raster_layer_count`、paint 范围 |
| **跟手** | 输入不堵在 GPU | 慢 Raster 注入下仍处理 pointer |
| **稳帧** | vsync 节奏可解释 | `missed_vsync`、frame 间隔分布 |
| **可重复** | 同场景可回归 | JSON 基线 + `go test` |

P3 §7.1 + S0/S2/S4 是 **最低关门线**。  
P4 的 S5/S6 把「列表页」也纳入引擎手感，仍不算 L3 控件库完成。

## 2. 验证怎么做（三层）

```text
① 单元/契约     go test ./ui/...   （脏区、管道、坐标、依赖）
② 场景探针      examples/ui_l1_* + 指标 JSON
③ 回归对比      同一机器存 baseline，改动后比 delta（禁止无基线谈「优化了」）
```

### 2.1 必采指标（L1）

| 指标 | 用于 |
|------|------|
| `ui_cpu` / `raster_cpu` | 线程占用 |
| `layout_count` / `paint_count` | 是否全树 |
| `raster_layer_count` | 是否只脏层 |
| `frame_build_ms` / `frame_raster_ms` | 分轨耗时 |
| `frame_time_p50` / `p99` | 流畅与卡顿 |
| `missed_vsync` | 掉帧 |
| `pipeline_depth` | 背压是否健康 |
| `present_count` | 是否空转 Present |
| RSS / 斜率（soak） | 内存是否爬升 |
| `gpu_submit_count`（若可） | 是否碎提交 |

### 2.2 场景矩阵（L1 相关）

| ID | 场景 | 通过标准（方向） |
|----|------|------------------|
| **S0** | 空窗 IDLE | CPU&lt;1%；present 不狂刷 |
| **S1** | 低频脏点 | 非脏时段不 raster |
| **S2** | 单 Spinner | 1 layer/frame；layout=0；UI CPU 上限 |
| **S3** | 多 Spinner | 禁止 paint∝全树 |
| **S4** | 复杂静态+1 动画 | 静态层 re-raster=0 |
| **S5** | 虚拟列表滚动（P4） | bind/paint 上界；延迟≤1 帧 |
| **S6** | 拖拽（P4） | 最新点；不整表 layout |
| **S8** | resize | 一次全量后恢复局部 |
| **S9** | 遮挡/恢复 | 无泄漏、可恢复 |

### 2.3 建议基线流程（正向优化的唯一合法方式）

```text
1. 固定机器 + 固定 env（DISPLAY、GPU、scale）
2. 跑 S0/S2/S4（P3）写入 baseline JSON
3. 任何「优化」PR：同场景对比
   - 指标不劣化（或可解释的权衡）
   - 语义/像素门禁仍绿
4. 优化失败 → 回滚（禁止「感觉更顺」合入）
```

**没有 baseline 的优化，不算正向优化。**

## 3. 能否「保证」CPU / 内存 / FPS 达到「最优」？

| 说法 | 能否保证 | 说明 |
|------|----------|------|
| **帧成本模型正确**（∝脏区，非∝全树） | **能作为门禁保证** | S2/S4 计数红就不过关 |
| **空闲近 0% CPU** | **能作为门禁保证** | S0 |
| **输入不因 Present 同步阻塞** | **能作为门禁保证** | 管道+注入测 |
| **同场景可回归的 FPS/帧时** | **能保证「达标+不回退」** | 相对 baseline 与门槛，不是全球第一 |
| **绝对最低 CPU/内存/最高 FPS** | **不能数学保证** | 依赖 GPU 驱动、cgo、字体、内容复杂度、系统合成器 |
| **任意重特效仍 60fps 且近 0% CPU** | **不保证** | 与 Flutter 一样：重 saveLayer/blur 有成本 |
| **一次优化永久最优** | **不能** | 需持续基线与门禁；P6 再抠极限 |

### 诚实边界（写进预期）

```text
保证的是：
  · 架构不强迫你为 1 个 Spinner 付全页代价
  · 空闲不空转
  · 关键路径可测、可回归、可证明变好或不变差

不保证的是：
  · 比所有原生 toolkit 每一个场景都更省
  · 无内容上限的 60fps
  · 不跑门禁也「一定最优」
```

### 与「正向优化」的关系

| 原则 | |
|------|--|
| **先正确，再刷分** | 脏区错了，再抠 submit 也假丝滑 |
| **每刀可证明** | 同场景 JSON delta |
| **禁止用降画质装绿** | 除非显式质量档（另开开关） |
| **内存** | soak 斜率≈0；峰值有解释 |
| **FPS** | 看 p50/p99 与 missed_vsync，不只看平均 |

**L1 完成 = 原生级引擎手感的「可验收基线」达成，并具备持续正向优化的测量体系。**  
**不是** = 性能调优工作永远结束、或已达理论最优。

## 4. L1 关门检查清单（给人用）

```text
□ P0–P3 任务卡 DoD 全勾
□ 真源 §7.1 F 项全勾
□ S0/S2/S4 在固定机器出 JSON 基线并入库（或 docs/tmp 存档）
□ go test ./ui/... 绿
□ ui 无 import gpu
□ 慢 Present 时输入仍通（跟手契约）
□ 文档记录：机器型号、GPU、scale、命令、结果
□ （推荐）P4 大纲已排期，滚动场景不无限期空窗
```

通过后可宣称：

> **L1 UI 引擎达到本仓库定义的原生级引擎手感门禁；具备可回归的性能基线。**  

不可宣称：

> **任意 App/任意控件已原生最优。**
