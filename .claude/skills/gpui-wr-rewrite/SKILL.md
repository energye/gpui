# gpui-wr-rewrite — W 矩阵级调度回流（推翻整波重写）

> **与收敛后 skill 的分工：**
> - `wr-implement` = 能力实现回流——**被本 skill 调度**
> - `wr-close` = 关 R/C 完整生命周期（3 模式）——**被本 skill 调度**
> - `metrics-audit` = 指标族 A–J 正误审查——**被本 skill 调度**
> - `wr-engine` = 底层修复回流——**被本 skill 调度**
> - **本 skill** = W 矩阵级调度——**调度层，不直接写代码**
>
> **真源：** `docs/ENGINE_UI_WIDGET_RENDER.md` **§5 分期表 + §2 主表 + §3 组合表 + §10 修订表**；`docs/ENGINE_UI_RENDER_BASE.md` §22.1。若与真源矛盾，以真源为准——停下报告，不要自决。

## 0. 硬规则（W 矩阵 · 独立真窗）

| # | 规则 | 说明 |
|---|------|------|
| **U5-W** | 该 W **每一个**主能力 R **必须**有独立 `examples/ui_wr_r*` 真窗 | 禁止用组合窗代替关 R |
| **U6-W** | 该 W **每一个**组合窗 C **必须**有独立 `examples/ui_wr_c*` 真窗 | 组合窗做集成；**不能**代替单能力窗关 R |
| **状态真源** | 只认 **§2 主表**（R）+ **§3 组合表**（C）+ **§5 分期**（W）+ **§10 修订** | 升维/降级只改这些章节 |
| **空目录** | `examples/ui_wr_*` 0 文件 = 未建 | 必须 wr-close 模式 1 建窗，不得标 ✅ |

历史「推翻整波」错误回流：

| 错误回流 | 表现 | 为何危险 |
|----------|------|----------|
| **逐个 R 独立修底层，重复修同一底层洞** | R4/R11/R18 各修一次 BoundaryCache | 浪费 + 不一致 |
| **没有 W 矩阵级状态治理** | §5/§2/§10 没标 🔄 | docs 漂移 |
| **批量重写无调度** | 漏触发某些 R/C | 半绿 |
| **用组合窗代替单 R** | 用 C 的绿关未建/未绿的 R | 违反 U5 |

本 skill 固化：

**W 矩阵级状态降级（§5+§2+§3+§10）→ 逐个 R 独立真窗回流 → 逐个 C 独立真窗回流 → 底层洞批量修 → 批量重跑 → 状态升维**

---

## 1. 触发与输入

- 一个/多个 W id + 「推翻重写」
- 一组 R/C id + 「批量重写」

解析：`W_IDS` 与/或 `R_IDS`/`C_IDS`；都没给则停下问用户。

## 第 0 步：读真源 + W 矩阵定位

**必做**——禁止凭记忆。

### 0.1 读 §5 分期表（W 涉及集权威）

取该 W：`状态` / **必须绿的单能力窗**列表 / **必须绿的组合窗**列表。

```
| W0 | ✅v2 | R0、R12、R16（各独立真窗） | C0（仅集成） |
| W1 | … | R2/R3/R3b/R5/R9/R12b | C1 |
```

**⚠ §5 是涉及集权威。** 禁止只按 §2「波次」列肉眼筛（跨波词会漏）。

**硬校验：** 涉及集里**每一个** R 与 **每一个** C 都必须在后续回流中有**独立包** `examples/ui_wr_<id>_*/`（含 main.go）。缺包 → 该 id 视为 ⬜，走 wr-close 模式 1。

### 0.2 读 §2 主表（按 §5 R 列表逐行）

每行取：`ID` / `PACKAGE` / `WINDOW=1200×800` / `CLOSE_SECONDS` / `当前状态`。

### 0.3 读 §3 组合表（按 §5 C 列表逐行）

每行取：组合 ID / 包名 / 窗口 / 关闭用时长 / 覆盖的 R（仅说明集成范围，**不代替**那些 R 的单窗）。

### 0.4 读 §10 修订表

取最新版本号。

### 0.5（可选）RENDER_BASE §22.1

多 W 调度时确认施工序依赖。

## 第 1 步：W 矩阵级状态降级

**必做。**

### 1.1 §5 分期表

| 原状态 | 降级后 |
|--------|--------|
| `✅` / `✅v2` | `🔄 W<n> 推翻重写` |
| `⬜` | 保持 `⬜` |
| `🔄` | 保持 `🔄` |

### 1.2 §2 主表该 W 所有 **R** 行

| 原状态 | 降级后 |
|--------|--------|
| `✅` / `✅v2` | `🔄` |
| `⬜` | 保持 `⬜` |
| `🔄` | 保持 `🔄` |

### 1.3 §3 组合表该 W 所有 **C** 行

波次/备注列：若写 `✅` → 改为 `🔄 推翻重写中`（组合窗也要重关独立包）。

### 1.4 §10 修订表加占位行

```
| <下一版本号> | W<n> 推翻重写：涉及 R=… C=…（进行中） |
```

**降级后** `read_file` 确认表格未破。

## 第 2 步：逐个 R 回流 + 逐个 C 回流

**核心。** 串行；本 skill 不写业务代码。

### 2.0 独立真窗存在性门禁（每个 id）

```
for each id in R_列表 + C_列表:
  PACKAGE = §2/§3 包名
  if examples/<PACKAGE>/ 无 main.go:
    → 必须 wr-close 模式 1 建独立真窗（禁止跳过、禁止用别的包冒充）
```

### 2.1 每个 R 的回流决策树

```
for each R in 该 W 的 R 列表:
  ├─ 能力就绪？否 → wr-implement（必要时 wr-engine）
  ├─ 真窗：
  │   ├─ ⬜ 或目录空 → wr-close 模式 1
  │   ├─ ✅ 推翻升维 / 🔄 → wr-close 模式 2
  │   └─ ✅ 优化增量 → wr-close 模式 3
  ├─ GPU 底层洞 → wr-engine
  └─ 门禁/指标 → metrics-audit
```

### 2.2 每个 C 的回流（与 R 同级，不可省）

```
for each C in 该 W 的 C 列表:
  ├─ 目录空 / ⬜ → wr-close 模式 1 建 ui_wr_c* 独立真窗
  ├─ ✅/🔄 推翻 → wr-close 模式 2 重关
  ├─ 组合窗只做集成回归，**不**重判所覆盖 R 的单能力门禁
  └─ **绝不**用 C 的绿去把未建/未绿的 R 标 ✅
```

### 2.3 调度纪律

- 调度层，不直接写代码
- R 与 C **全部**串行（先 R 后 C，或按依赖；禁止并行改底层）
- 每个 id 回流完确认：有独立包 + 状态升维；否则停下排查

### 2.4–2.5 底层洞批量收集与定点修（wr-engine）

同前：`HOLE_LIST` 去重 → 逐个 wr-engine → 修完重跑该 W 全部相关 R **与** C 真窗。

## 第 3 步：批量重跑验证

```bash
export LD_LIBRARY_PATH=$PWD/lib WGPU_NATIVE_PATH=$PWD/lib/libwgpu_native.so
for R in 该 W 全部 R: RUN_SECONDS=<CLOSE> go run ./examples/<r_package>
for C in 该 W 全部 C: RUN_SECONDS=<CLOSE> go run ./examples/<c_package>
```

- 任一 R/C 缺包或 FAIL → 不得 W 升维
- 批量 metrics-audit 审每个 R（C 按集成字段审）
- 全绿才进第 4 步

## 第 4 步：W 矩阵级状态升维

**只写 §5 + §2 + §3 + §10。**

### 4.1 §5

`🔄 W<n> 推翻重写` → `✅v2（推翻重写后）`（且该行列出的 **每个** R/C 均已独立真窗绿）

### 4.2 §2 该 W 所有 R

`🔄` → `✅v2`；首次关闭 `⬜→✅`

### 4.3 §3 该 W 所有 C

`🔄` → `✅v2`（或 `✅ 组合窗`）

### 4.4 §10 占位 → 正式行

```
| <版本> | W<n> 推翻重写 ✅v2：R=… 各独立真窗；C=… 各独立真窗；底层洞… |
```

## 输出格式

```
✅ W<n> 推翻重写收口

涉及 R（均独立真窗）：…
涉及 C（均独立真窗）：…

状态降级：§5 + §2 各 R + §3 各 C + §10 占位
逐个回流：R… / C… → ✅v2
批量重跑：全部 R+C PASS；metrics-audit PASS
状态升维：§5/§2/§3/§10
```
