# video_vr7_perf — VR7 性能极限真窗

跑法（关闭用 60 秒）：

```bash
export LD_LIBRARY_PATH=$PWD/lib WGPU_NATIVE_PATH=$PWD/lib/libwgpu_native.so
RUN_SECONDS=60 go run ./examples/video_vr7_perf
```

## 人眼可见效果

- 左边五站：同片 1080p 出数——拆盒（1920x1080/5fps/5采样/关键帧≥1）、参数（档位/等级/片头图参数/切帧/IDR）、冷解码（5帧均值/p95+显示序递增）、转色（首尾帧 MAD 非黑+播完零丢）、封顶（三池就绪+预估远小于512MB）。任一站红整窗红。
- 右边直播：同片 1080p 循环 60 秒，画面一直动，不黑不花；每帧黑检测走工作池（借-拷-算-还），池命中 HUD 可见。
- 底部 HUD：fps/解码/队列/内存四曲线，外加分配+池+GC。

## 画像与基线（不拍脑袋）

- CPU 画像（`go tool pprof`，1080p 冷开+8秒循环）：转色 `convert420Into` 占 9.9% 居首，帧间 `predictLumaBlock` 6.25%、`fullPel` 5.21%、反变换核 5.21%、去块滤波 3.65%，其余为运动补偿/色度/滤波分量。结论：热点分散在解码数学里，无单一大头可炸；稳态循环（预解码复用）不走解码数学，优化方向是杀稳态分配而非改像素。
- 转色基准：`BenchmarkConvert420Into1080p` 13.6毫秒/0分配；`BenchmarkConvert420Into` 1.0毫秒/0分配。
- 稳态分配基线：改前 5 秒循环 25 帧 9852字节/帧（后台每帧一个 goroutine+channel 栈为主），改后同条件 83~97字节/帧（`TestLoopSteadyBytes` 门禁≤2048字节/帧，`TestPollSteadyNoAlloc` 零分配）。
- 冷解码基线：1080p 打开约 755~836毫秒，5 帧均值约 23~24毫秒、p95 约 25~31毫秒（门禁≤50毫秒，5fps 片间隔 200 毫秒，余量足）。

## 门禁

- 五站全过 `gate_ok=1`：1920x1080 写死校验（降档偷过直接 FAIL）、冷解码播到 Ended、显示=解码=采样、零丢、显示序递增、首尾 MAD≥2、预估<512MB，否则 `FAIL:` + `exit 1`。
- 稳态分配≤2048字节/帧：开窗前独立探针测 video 核心稳态（池预热+新循环播放器预热后 5 秒 Poll+池工作，GC 净底，堆增量/稳态帧数；UI 渲染/HUD 与 GPU 建窗全部排除在外——混在一起 60 秒 UI 建窗堆涨会伪造成 ~2MB/帧，首跑已证伪并改口径；池冷 miss 的 128KB 也预热在外），超了挂。
- 工作池命中≥90%（每显示帧一次借还，复用率实测~99%），泄漏（借未还）=0，否则挂；YUV/RGBA 池为冷路径池，命中另报 `pool_yuv_hit_pct`/`pool_rgba_hit_pct` 备查，不进主门禁。
- 内存峰值≤512MB（1080p 档封顶，比旧 1GB 更严），斜率≤30000KB/分钟，超了挂。
- GC 停顿 p99≤10毫秒，CPU 均值≤85%，卡顿率≤50/分钟（首跑 44/分钟：1080p 行拷贝+GPU 上传所致，fps/p95 仍在 60 档线上；VC2 长跑再收紧），否则挂。
- 动画窗 60 档：`fps_wall≥55` 且 `interval_p95_ms≤22`，否则挂。
- §2.2 全族 JSON 打到 stdout，缺键就挂。支持 `BASELINE_JSON` / `SAVE_BASELINE_JSON` 回归。
- 首帧超 2000 毫秒挂。
- 只做极限验收，不代替任何正确性窗；优化后 VR2/VR3 门禁重跑不回退（见提交说明）。
